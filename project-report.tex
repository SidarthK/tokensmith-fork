\section{Project Overview}
This project improves TokenSmith's local-first RAG pipeline for database textbook QA by introducing a coverage-aware reranking stage for multi-hop questions. The current pipeline already performs extraction, chunking, hybrid retrieval (FAISS + BM25 + optional textbook-index signal), rank fusion, and LLM answer generation with local \texttt{llama.cpp} models. However, the current reranking strategy prioritizes per-chunk relevance, which can produce redundant evidence for complex questions that require multiple distinct facts.

The core goal is to implement a reranker that balances relevance with diversity/coverage. I am implementing an MMR-style greedy reranker where each candidate chunk is scored using query relevance and a redundancy penalty against already selected chunks.

\section{Current Progress}
\textbf{Implemented and integrated components completed to date:}
\begin{itemize}
    \item \textbf{Architecture grounding and implementation plan artifact:} Added a repository-level pipeline map and milestone execution plan documenting extraction $\rightarrow$ indexing $\rightarrow$ retrieval $\rightarrow$ reranking $\rightarrow$ generation.
    \item \textbf{Config-level support for new reranking mode:} Added \texttt{coverage\_mmr} controls in \texttt{RAGConfig}, including lambda and validation logic.
    \item \textbf{Coverage-aware reranker core:} Implemented MMR-style reranking with:
    \begin{itemize}
        \item relevance from cross-encoder query--chunk scores,
        \item redundancy penalty from chunk--chunk similarity,
        \item fallback lexical similarity if embedding similarity fails,
        \item deterministic greedy selection of top chunks.
    \end{itemize}
    \item \textbf{Pipeline integration:} Integrated reranking behavior into both CLI and FastAPI answer paths without changing frontend response schema.
    \item \textbf{Structured diagnostics logging:} Added rerank diagnostics (selected indices, mode, score details) into stored chat logs for analysis.
    \item \textbf{Test coverage additions:} Added unit tests for MMR behavior (diversity preference, determinism, edge cases) and an integration test for \texttt{get\_answer()} rerank-index mapping behavior.
    \item \textbf{Benchmarking support:} Added a multi-hop benchmark slice and a comparison runner script for baseline rerank vs coverage-aware rerank.
\end{itemize}

\textbf{Repository workflow progress:} Work is isolated in branch \texttt{sk/project-dev} with incremental commits matching component milestones, while \texttt{main} is kept aligned with the upstream TokenSmith baseline.

\section{Challenges and Observations}
\textbf{Challenge 1: Relevance-only reranking can overfocus on one subtopic.}
In early behavior, top chunks often repeated similar context instead of covering separate sub-questions. This confirms the proposal motivation for explicit diversity pressure.

\textbf{Challenge 2: Multi-objective tuning.}
MMR introduces a relevance-diversity tradeoff. If lambda is too high, retrieval remains redundant; if too low, chunks become diverse but less directly useful. This requires empirical tuning on multi-hop benchmarks.

\textbf{Challenge 3: End-to-end benchmark reproducibility.}
Some local benchmark runs are sensitive to environment dependency versions (for example NumPy compatibility and optional judge imports). This impacts automation stability and requires a controlled environment lock for fair final comparisons.

\textbf{Observation:} The existing TokenSmith architecture is modular enough that reranking upgrades can be inserted with limited disruption to retrieval and generation APIs.

\section{Background and Related Work}
The work is grounded in RAG literature and classical IR diversification ideas. In practice, TokenSmith already applies rank fusion and cross-encoder reranking; this project extends that final stage toward set-aware selection inspired by Maximal Marginal Relevance (MMR), where ranking decisions are conditioned on previously selected evidence to reduce redundancy and improve coverage for multi-hop prompts.
